# Silicon Extend 4.1: no telemetry

At the Carbon's request, Extend records no telemetry. Versions: the `extend` CLI 4.1.0,
`silicon-extend-client` 4.1.0 and the service 4.1.0 (database schema unchanged). The protocol crate
(2.0.0), the desktop apps and the Android app are unchanged.

- **CLI.** No event is sent after a command. `extend config set telemetry on|off`, `get` and `unset`
  still exit 0 and say there is nothing to turn on or off; an old `telemetry` value in `config.toml`
  is ignored and dropped at the next save, and `EXTEND_TELEMETRY` is not read.
- **Client.** `Authed::telemetry` and `ClientBuilder::telemetry` are deprecated no-ops. Every call
  says `X-Extend-Telemetry: off`, so an older service records nothing either, and sign-in asks
  Silicon Accounts to record nothing (`X-Accounts-Telemetry: off`).
- **Service.** `POST /api/v2/telemetry` is gone (404; the 4.0 CLI ignored the answer, so nothing
  changes for it), commands leave no event, and nothing is exported to Space Station (the
  `space-station` dependency is gone). Calls to Silicon Accounts carry `X-Accounts-Telemetry: off`.
  The old `telemetry` table stays untouched; no migration.

## For operators

Remove `EXTEND_SPACE_STATION_KEY` from the runtime secret: the service names it at startup as a
variable it no longer reads, and neither the AWS renderer nor the parallel installer passes it on.
